# 构建与交付

本目录负责万象理库的编译、增量缓存与 npm 发布打包。在总流程中，它让开发者改一个库时只编译该模块声明的输入：不先安装 .NET、不等全量重编，产出与 `package.json` 的 `exports` / `files` 一致的中立核分发物。

## 状态所有权
- 增量缓存状态由 `.build-stamps/` 下的输入摘要持有，仅在产物原子替换成功后写入。
- 每个真实工作树一个常驻构建服务与一份发布者归属；服务默认空闲十分钟退出，worker 默认累计 128 个项目后在构建边界轮换。不同工作树互不共享。
- 输入清单以各模块显式 `.fsproj` 及其源码为唯一事实来源，不设第二份文件配置。
- 构建产物与发布包白名单由 `package.json` 的 `exports` 与 `files` 裁定。

## AXIOM
1. [开发者] 修改一个库时，不应编译其他库，也不应先安装 .NET。
   - 理由：维护成本包括等待验证的时间。
2. [使用者] npm 包必须在没有本仓源码、旧仓和编译器的目录中使用。
   - 理由：只有真实安装才能暴露漏掉的包文件、缺的类型声明和反向依赖；开发期的 `file:` 链接看不出来。

## LEMMA
1. [AXIOM 1] 每个已实现子模块一个显式 fsproj；直接调用 npm 上的 Fable 编译器，不建立第二份源文件清单。组合通过公开 ESM 入口使用参与者，构建不内联兄弟库。
2. [AXIOM 2] 交付检查用实际 tarball，不用 workspace link、NODE_PATH 或源码回退。
3. [AXIOM 2; LEMMA 1] 公开入口由已实现模块推出：每个带 fsproj 的模块恰好一个 exports 项，指向构建产出的入口文件，类型声明在 files 白名单里；没有指向不存在模块的入口。
4. [AXIOM 1; LEMMA 1] 构建按模块增量。模块的编译输入是 fsproj 文本、其显式源文件、Node 身份、`scripts/` 下的构建模块，以及已安装的 Fable 编译器、FCS、元数据、运行库、esbuild 及其依赖的实际内容；包清单与锁文件同样参与摘要，不只比版本号。摘要未变且 `dist/<name>` 与记录的逐文件摘要一致时跳过该模块；`--force` 或 `WANXIANGLI_BUILD_FORCE=1` 强制重编选中范围。产物不得含进程号、时间戳等非输入信息，同样输入得到同样字节。
5. [AXIOM 1; LEMMA 4] 构建开始时记录选中模块的输入，发布各模块前和整次构建结束前复查；缓存命中的模块也要复查。输入改变或不可读时构建失败，失效模块的摘要不保留，下次只补编失效模块，不自动转成全库强制重编。
6. [AXIOM 1; LEMMA 4] `node scripts/build.mjs`（或 `npm run build`）连接本工作树的常驻构建服务：请求按顺序执行，checker 按引用名称、DLL 内容与编译选项复用，每个项目解析前与输出后清项目缓存。worker 到累计项目上限后在构建边界退出，服务空闲到时限后退出；编译失败丢弃 worker，工具链内容改变替换 worker，构建代码或 Node 身份改变重启服务。全部命中缓存时不启动 worker。跨命令共享的是初始化，不是某个项目的检查结果。
7. [AXIOM 1; LEMMA 6] 每个真实工作树只有一个发布者。归属目录靠原子改名取得，内含 PID、启动时间与随机代号；退出与故障接管把旧归属移进不可覆盖的旧代目录。编译 worker 只写临时产物，服务确认输入与归属后才发布；客户端断开不把未知结果说成成功。
8. [AXIOM 1; LEMMA 6] 空闲时限与 worker 项目上限是正整数限额，可用 `WANXIANGLI_BUILD_IDLE_MS`、`WANXIANGLI_CHECKER_PROJECT_LIMIT` 调整；上限只限寿命，不冒充字节预算。参数与实测记录见同目录 `BUILDING.txt`。

## SPEC（操作员与构建流程）

1. **单模块与增量构建**：
   - `node scripts/build.mjs <module>` 只编译指定模块及其声明的编译输入，不跨工程编译其他子模块；不带模块名则覆盖全库。
   - 源码未改动时重复执行命中缓存跳过；源码或输入摘要变化时只补编失效模块；`--force` 强制重编选中范围。
   - 编译报错时构建以非零状态码结束，不覆盖既有正常产物，不发布半成品；修复后重跑普通构建即可。
2. **服务查询与停止**：
   - `node scripts/build.mjs --status` 查询本工作树服务，查询不会启动服务；`--stop` 等当前请求结束后退出服务。
   - `--status` / `--stop` 不能与模块名或 `--force` 同时使用；`--json` 交出机器可读的结果；不认识的双横线选项直接报错，不静默忽略。
   - 停止后，全命中缓存的构建不再加载 checker。
3. **导出与发布一致性检查**：
   - `package.json` 的 `exports`、`files` 与实际实现的子模块必须一致；缺失类型声明、指向不存在的构建输出或遗漏 exports 映射时构建报错拒绝。
4. **干净交付物检查**：
   - `npm pack` 触发 `prepack` 先构建，产出 npm tarball；禁止把 `.tgz` 提交进 Git。
   - 检查把 tarball 解包到空目录里，真实导入并读类型定义；用 workspace link、NODE_PATH 或源码回退跑出来的「通过」不算数，那种环境里源码还在，漏打包也看不出来。
