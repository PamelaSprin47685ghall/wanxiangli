常驻构建

npm run build 自动管理本工作树的服务，不需要 agent 手工启动 checker。
npm run build -- association 只构建指定模块及其声明的编译输入。
npm run build -- --force 忽略产物缓存。
npm run build -- --status 查询；npm run build -- --stop 停止。

默认空闲十分钟退出；默认累计 128 个项目后在构建边界轮换 worker。
WANXIANGLI_BUILD_IDLE_MS、WANXIANGLI_CHECKER_PROJECT_LIMIT 可调整这两个正整数限额。
清项目缓存保留初始化收益，不保留已检查的项目结果。
首次构建和轮换后的首次构建仍有初始化成本。

使用记录

默认仍空闲十分钟退出。--status 不延长空闲期限，也不写使用记录。
实际进入 worker 编译阶段的请求记录在 .build-service/usage.json，
状态查询和全缓存构建不计入；记录留在本机，不上传，不进入 Git。
intervalMs 是两次编译开始之间的间隔，idleMs 是上次完成到本次开始的间隔；
时间戳使用 Unix 毫秒，durationMs 只覆盖编译请求及发布收尾，不包含初始化。
服务重启后保留上次记录，超过十分钟的间隔也能观察到。

totals 保存累计次数，samples 只保留最近 256 次编译。
reuse.created 是新建 checker 数；reused 是使用已检查过项目的 checker 的次数，
reusedAcrossBuilds 只计本次请求开始前已有 checker 的复用，避免把全量构建内
模块间的复用误当成常驻收益。库中每个项目检查分别计数。
workerMemory 与 serviceMemory 记录编译返回及收尾时的 RSS、JS 堆与外部内存，
单位为字节；这是内存快照，不是峰值、空闲曲线或 macOS footprint，也不强制 GC。

编译失败仍记录；进程强杀留下 pending，下次编译将其标为 unknown。
缺失的复用报告计入 missingReuseReports，不猜测为零。累计数与最近样本分别统计。
记录损坏或不可写时保留现有文件，在 service.log 报告并停用本服务的记录，
不因此改变编译结果；修复记录文件后重启服务即可恢复。删除 usage.json 可清空记录，
应先 --stop，避免活动服务写回旧记录。

可选并行编译

npm run build -- --parallel 使用 2 个编译进程；--jobs N 可选 1–4 个。
不加选项仍为串行。指定模块同样支持，例如 npm run build -- association advisor --parallel。
实际进程数不超过失效模块数；全命中缓存不启动编译进程。并行度变化不使产物缓存失效。
每个进程内顺序编译并复用 checker，每个项目仍清理缓存。
保留第一个进程供后续命令复用；额外进程在本次构建后退出，避免空闲时多份内存常驻。
不同工作树各有独立并行额度；--jobs 不是整台机器的进程总上限。

同一工作树的构建请求继续排队。模块只在临时目录并行计算，全部成功并复查输入后，
才由服务逐模块发布。编译错误或 worker 强杀会先回收所有本次进程，不发布临时产物。
发布阶段 I/O 故障仍沿用原有边界：当前模块回滚，已发布模块可能保留，整次构建报失败。

JSON 结果的 jobs 是实际进程数（全缓存为 0），compiledByPids 列出参与进程，
workerPid 是保留的常驻进程。usage.json 的 workers 记录每个进程的复用、内存与退出情况；
workerMemory 为各进程返回时快照的合计，并非同一瞬间的峰值。fcsMs 是各进程耗时之和。
