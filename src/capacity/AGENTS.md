# capacity

层：账本。容量不变量对账的唯一 owner；不得 import 宿主 SDK，不持有账本、不改状态、不修复、不关停。npm 入口 `wanxiangli/capacity`。

# AXIOM

1. [使用者] 并发容量的账面（credit、令牌、托管、等待者）一旦彼此不一致，宁可失败关闭，也不能继续按错账调度。
    - 理由：错账会让并发超出用户在 `wanxiangshu.mjs` 设下的上限，或让等待者永远等不到容量（execution-model-routing [003][012][013]）。

# LEMMA

1. [本模块 AXIOM 1] 对账只读一次一致快照，回答 NoOp 或 FailClosed；不修复、不重试。
    - 推理：对账结论只有在快照一致时才有意义；修复要求知道是谁的错，那是账本 owner 的事。
2. [本模块 AXIOM 1] 七类失败独立判定、全部报告、次序固定：活跃数越界、令牌状态计数不符、账本与令牌 credit 分叉、令牌 owner 不可追溯、等待者 owner 不可追溯、执行无托管、计数器回退。
    - 推理：只报第一项会掩盖并存的第二个错；固定次序让诊断可比较。
3. [本模块 AXIOM 1] 形状不合法的快照直接抛错，不当作 NoOp。
    - 推理：把坏输入当“没有问题”就是静默放行。

# SPEC

1. [LEMMA 1, 2] 一致快照为 NoOp；每类失败单独触发恰好那一项；多类并存时全部按固定次序报告；结果冻结。
    - 证明：`tests/001.test.mjs`。
2. [LEMMA 3] 缺数组、非整数计数、非字符串身份字段抛错。
    - 证明：`tests/001.test.mjs`。
