# 执行失败与恢复

这个入口帮助调用方区分已经发生的失败、尚不明确的外部结果，以及接下来允许做的事。它不认识具体宿主 SDK，宿主事件和错误文字由万象通解释。公开对象及字段见 `index.d.ts`。

`ExecutionFailurePolicy` 仍是纯决策：输入已分类失败、执行阶段、精确容量许可和 provider 预算事实，返回保持、等待、重试或结束等决议。它不拥有预算、不释放资源、不发送请求。未知结果不能冒充已知未发生；时间和预算可以结束等待，但不能据此重复外部效果。

`ProviderRecovery` 拥有一次恢复的合作顺序：接收失败决议，等待预算持久接纳，再等待精确旧请求停止，重新读取活动授权，交给发送能力。它也承接普通执行和委派调用的不同返回方式。预算、Journal Current、授权和物理发送均留在各自对象，不建立第二份状态表。

相同运行已经持久关闭时，迟到失败保持静默。活动授权缺失本身不表示关闭或被接替；没有对应关闭事实时仍返回失败。长工作等待停止回执后重新查询关闭状态，查询由调用方提供。

重复已接收恢复仍按原协议等待停止回执；Denied、未知和被新授权替代分别返回，不自动再次发送。发送材料和硬停止分类由外侧提供，核不从自由错误文本猜测。长工作续行在旧请求停止后再次读取授权；排队回执、物理接受与完成不得互相替代。效果 Promise 拒绝原样传播，不增加恢复循环。

`ProviderAttemptStopFence` 持有精确 session/run 的停止观察与等待者。等待超时仅返回 TimedOut；取消登记只影响对应等待，不证明 provider 没发生效果。

`RecoveryAttemptPlanStore` 持有进程内待绑定与已绑定的尝试计划，以及仍被现有调用消费的干预记录。原绑定、重放、消费和清理行为不因本轮新增协调者改变。

协议转换和资源文案留外侧，角色身份、宿主生命周期和整个产品 Context 不进入本入口。适用根目录万象理约定；测试用于本次差分自保，不代替使用者体验。
