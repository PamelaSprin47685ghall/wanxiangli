# attachment-lease — 附着会话租约与复用

层：内核纯计算与进程内状态自治。独立 npm 入口 `wanxiangli/attachment-lease`。在总流程中，本模块负责受管附着子会话（Companion、Bookkeeper、同步副本）的单飞创建去重、基于持久关联的精准复用与失败清理。

## 状态所有权
- **AttachmentLeaseRegistry** 独占持有 `(owner, kind)` 租约映射与在途单飞并发对象。
- 模块不直接调用宿主创建物理会话，不读写持久存储。

## AXIOM
1. [使用者] 一个 Attached 种类复用的子会话只能是其持久关联点名、且 agent 与 title 精确相同的那个；没有持久关联时一律新建，不收养长得一样的无关联子会话。
    - 理由：单一租约机制；避免将无关联会话误绑定导致状态错乱。
2. [使用者] 新建或替换出来的子会话只有在关联写成后才算真实；关联失败必须把它弃掉，已复用的旧子会话从不弃。
    - 理由：失败的 link 会留下孤儿会话并在恢复时产生歧义。
3. [使用者] 进程内租约注册表自治管理租约映射，并在首次 ensure 时单飞去重，避免并发创建重复子会话。

## LEMMA
1. [AXIOM 1] 无 restoreHint 时直接新建；有 restoreHint 时，仅当列表中该 id 恰好存在且配置完全相同时复用，属性不符报冲突，多于一个报歧义。
2. [AXIOM 2] 新建或替换出的会话在失败时必须中止释放；已复用的旧会话失败时不中止。
3. [AXIOM 3] `AttachmentLeaseRegistry` 支持原子 bind、按所有者查找、反向查找、并发 ensure 去重与清理。

## SPEC（调用方流程）

1. **复用判定**：
   - 调用方传入当前会话候选与提示信息。库决定是复用既有会话、新建独立会话，还是因歧义返回拒绝。
2. **单飞创建去重**：
   - 并发请求通过 `ensure` 竞争创建许可，首个调用获得执行权，并发请求共享在途任务；完成后注销占位。
3. **关联失败安全清理**：
   - 当建立关联失败时，系统仅清理本次新创建的临时会话，已复用的既有会话不受影响。
