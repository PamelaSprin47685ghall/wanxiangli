# delegation

层：内核。不得 import 任何宿主 SDK。

# AXIOM

1. [使用者] 派工就是产生真实效果：起一个子会话、跑一条命令。做重了会真的做两遍。
    - 理由：真实外部效果不可逆（总规则 LEMMA 1）。

2. [使用者] 一次工作的完成结果只能由它的 owner 认领，别人只能读。
    - 理由：两个地方都能宣布"这次工作完成了"，记录就不可信。

# LEMMA

1. [本模块 AXIOM 1] 只有确切的"已承接"才算成功；传输回执不算。
    - 推理：传输层收下请求不等于对方接手。用回执当成功，会让调用方以为有人在做，而实际上没有人。

2. [本模块 AXIOM 2] 完成单实例：晚到或旧的回执幂等忽略，不得结算新的工作单元。
    - 推理：认领两次会把一次工作记成两次，记录从此不可信（总规则 AXIOM 1 要求逐轮说清）。

3. [本模块 AXIOM 1; 总规则 LEMMA 5] 忙碌时把新任务作为追加提示投给既有工作单元，不新建。
    - 推理：新建等于两条工作同时改同一份东西。追加提示是可撤销动作，不需要额外的登记与清理。

4. [本模块 AXIOM 1] 按后果分型，不按名字分型：新建独立工作者、续做既有工作者、委任顶层道路，是三个不同的动作。
    - 推理：后果不同的动作如果同名，调用方无法判断自己会得到什么。
