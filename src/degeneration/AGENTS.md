# degeneration — 请求耗时检测与可靠性计数

层：内核纯计算与指标计数。独立 npm 入口 `wanxiangli/degeneration`。在总流程中，本模块为 LLM 请求耗时提供无先验、自适应的指数分布最大似然估计（P99 阈值），并在请求耗时严重异常时发出警报；同时提供可靠性不可逆指标统计。

## 状态所有权
- **RequestLatencyDetector** 独占拥有各会话的衰减充分统计量（k 完整样本数、m 删失样本数、S 衰减总耗时、n 观测总数）。
- **ReliabilityDiagnosticsStore** 独占持有 12 类不可逆观测计数器的单调计数状态。
- 模块不读系统时钟，不做物理 I/O。

## AXIOM
1. [使用者] 一个 session 的请求耗时显著超出其自身历史分布时，调用方需要一条随该 session 自适应的明确阈值，而不是全局固定值；样本不足以支撑 p99 时宁可不判。
2. [开发者] 判定只消费调用方传入的耗时观测；库内不读时钟、不做 I/O。

## LEMMA
1. [AXIOM 1] 耗时服从指数分布 Exp(λ)，无全局先验。每次记录新耗时先乘衰减因子（γ = 0.98）再累加；右删失样本只累加耗时 S，不增加样本数 k。
2. [AXIOM 1] 前 99 条观测处于新手保护期，计算阈值为正无穷（不触发异常打断）；观测数达到 100 且存在完整样本时，按 P99 公式计算确切阈值。
3. [AXIOM 1, 2] 单会话内存占用 O(1)；快照返回只读数据副本，外部修改不影响内部统计状态。

## SPEC（调用方流程）

1. **耗时观测与自适应阈值计算**：
   - 每次 LLM 请求完成后调用方记录实际耗时或超时删失时长。系统更新统计量并计算当前会话自适应 P99 阈值。
   - 处于新手保护期或样本不足时，阈值保持无穷大，避免误伤初次长请求。
2. **会话重置与清理**：
   - 会话关闭时调用 `Forget` 释放当前会话统计字典；测试或全局退出时支持 `Clear`。
3. **可靠性不可逆指标记录**：
   - 发生冲突、队列满、某类恢复决定（`recovery:observeOnly`、`recovery:markTerminal`、`recovery:failClosed` 等）或流中止这类不可回头的事件时，通过 `ReliabilityDiagnosticsStore.Record(kind)` 单调累加；快照只读，供人观察，不参与任何判定。
