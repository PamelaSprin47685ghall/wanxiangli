# capability — 角色能力矩阵与权限判定

层：内核纯计算。独立 npm 入口 `wanxiangli/capability`。在总流程中，模型看得见哪些工具、执行时放行哪些动作，读的是同一份能力事实；本模块独占这份事实，让“看不见”与“做不了”不会分叉。

[程序待改] 宿主工具词根写死在本核：计划提交入口叫 `todowrite-for-plan`，实用工具名 `skill` / `assume` 列在 `OfficeMatrix`。这些名字是宿主与模型对话用的词，目标由万象通提供。已登记在根《例外清单》。

## 状态所有权
- **OfficeMatrix** 独占拥有角色到能力集合的映射字典。
- **ToolSurface** 独占拥有能力到宿主工具名称的映射与实用工具放行判定。
- **LiveHostConfigStore** 独占持有可变宿主活配置引用的纯进程内自治对象。

## AXIOM
1. [使用者] 一个角色只能做它被授权做的事；而且“看不见”与“做不了”必须是同一件事。
2. [使用者] 同一角色换执行者（重试、换模型、换档位）权限不变。
3. [使用者] 内部专用的动作不进普通角色的工具面。

## LEMMA
1. [AXIOM 1] 能力 = 角色 * 请求类型。工具面投影与执行前检查读取同一份能力事实。
2. [AXIOM 1] 角色无法解析或未知时，工具面置空且运行时拒绝一切调用。
3. [AXIOM 1] 实用工具名（`skill`、`assume`）不进办公能力矩阵，由 `admitsUtility` 单独判定：矩阵内角色可用，Advisor 一律拒绝，矩阵外的角色标签也拒绝。
4. [AXIOM 1] `LiveHostConfigStore` 自治维护深层配置树读写与类型安全核验。

## SPEC（调用方流程）

1. **角色工具面生成**：
   - 根据当前请求角色查询工具面。系统按矩阵返回允许使用的工具定义列表；未知角色返回空集。
2. **工具执行准入检查**：
   - 模型发起工具调用时调用 `admitsToolForRole`。只有在该工具属于该角色授权集合时放行，否则明确拦截。
3. **活配置安全读写**：
   - 通过 `LiveHostConfigStore` 进行深层配置读取或更新；写入时自动构建中间层级并在写入后核验。
