# pair-hint — 提示词配对与上下文重锚

独立 npm 入口：`wanxiangli/pair-hint`。在总流程中，本模块负责管理会话的上下文重锚边界（resetScope barrier）、提示词与工具结果的无损注入、协商机制（negotiate）以及旧工具过程的安全清理。

## 状态所有权
- **ScopeSession** 独占拥有当前会话的最新重锚边界、协商受理状态以及各轮次提示注入的覆写式视图。
- 计费回合与降幅判定已移交 `wanxiangli/scope-progress`；持久日志事实归底层 Journal 存储，本模块不保留冗余的业务状态副本。

## AXIOM
1. [使用者] 只有显式 resetScope 调用能清理旧上下文；真实 operator 输入与 reset 调用及结果必须保留。代理答复属于可清理过程；模型自行决定经验与原文交接。
2. [使用者] 用户消息注入与工具结果注入是两条独立、明确的 API，载体不能混淆。

## LEMMA
1. [AXIOM 1] 最新 reset 是唯一清理边界。重锚前的用户消息与 reset 记录保留，之后完整保留；旧普通工具调用与执行过程在 reset 处截断退役。
2. [AXIOM 2] 提示注入仅在发给模型的请求副本中呈现，不原地篡改持久化历史与原始用户输入；同一提示不重复追加。
3. [AXIOM 1, 2] 首次协商（`negotiate`）一经受理即解锁 `resetScope`，时序继续，不阻塞等待答复；答复到达后作为异步 steer 注入。
4. [AXIOM 1, 2] `assume`、`negotiate`、`askPreviousScope`、`resetScope` 等关键工具调用与成对结果穿越 reset 始终保留；旧 Scope 的思考过程（thinking）退役，最新 reset 之后的思考过程完整保留。

## SPEC（操作员与调用方流程）

1. **首次协商与重置激活**：
   - 任务启动时，系统通过强 steer 提醒执行首次协商。调用方调用 `negotiate(questions)`，一旦受理立即解锁 `resetScope`，调用方无需同步等待问答结果即可推进当前 Scope。
2. **上下文重锚与旧过程清理**：
   - 调用方发出 `resetScope` 时，本模块以该调用为边界：保留此前的真实操作员消息、关键协作工具调用与本次重置摘要；安全退役旧的临时思考过程与普通工具流水账。
3. **提示词与工具结果后缀安全注入**：
   - 根据语言环境（`zh-CN` / `en`）在请求副本末尾注入必要的系统提示与配对说明，底层原始消息与持久历史保持完全不变。
