# advisor — 顾问材料身份与专席管理

层：内核纯规则与进程内状态。独立 npm 入口 `wanxiangli/advisor`。在总流程中，本模块为操作员或工作流提供对顾问席位的材料增量规划、已交付事实去重、长寿命专席单飞创建与陈旧运行拦截。

## 状态所有权
- **AdvisorLedger** 拥有各会话已交付材料锚点的单调递增并集。
- **AdvisorSeatRegistry** 拥有各会话专席子进程的单飞创建任务与失败锁存。
- **SettledRunLedger** 拥有已结算运行标识，负责陈旧运行过滤。
- 不持久化数据，进程重启即丢弃内存记录。

## AXIOM
1. [使用者] 顾问只被交底一次：已经交给它的材料不重发，变化了的精确文本仍要看见；一次 carry 内显式重复的条目按顺序保留。
    - 理由：重发会让每次追问按完整上下文计价并混淆旧判断。
2. [使用者] 只有成功的咨询才算交底；失败或未确认不消费增量。
3. [使用者] 顾问的回答是它真的说出的散文；没有就是拒绝，不伪造建议。
4. [专席] 专席长寿命复用且单飞创建；创建失败后不得永久中毒，下次必须可重新尝试。

## LEMMA
1. [AXIOM 1] `materialKey` 由来源与精确文本编码构成；字面值与历史锚点身份严格隔离。
2. [AXIOM 1] `plan` 仅输出本次新增材料的 delta，整张 view 的锚点记录到 `deliveredAnchors`。
3. [AXIOM 2, 4] 专席创建单飞管理，创建失败标记 `CreateFailed`，下一次调用允许重试恢复。
4. [AXIOM 3] `answer` 提取最新一条非空白 assistant 散文，缺失返回 null。
5. [AXIOM 5] `SettledRunLedger` 严格拦截已被结算过的陈旧运行重放。

## SPEC（调用方流程）

1. **增量材料规划**：
   - 调用方生成完整上下文 view 传入 `plan`。系统比对 `AdvisorLedger` 已记录的锚点，只筛出未曾交底的新材料作为 delta 返回；没有新材料就无需再向顾问发一次冗余调用。
2. **专席获取与单飞保障**：
   - 通过 `AdvisorSeatRegistry.ensureSeatChild` 获取专席会话，并发调用共享创建任务；创建失败后安全释放，避免通道永久损坏。
3. **结果提炼与结算记录**：
   - 提取顾问的自然语言散文回答；通过 `SettledRunLedger` 登记运行终态，防止迟到回调或粘性重放造成重复结算。
