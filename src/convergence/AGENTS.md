# convergence — 多流因果有序合并

层：内核纯计算。独立 npm 入口 `wanxiangli/convergence`。在总流程中，本模块负责将多个并发写入者（writer）追加的事实日志合并为单调确定的因果全局序列，保证分布式或多进程并发历史在任何机器上均能重放出完全一致的状态。

## 状态所有权
- 纯算法逻辑，独占持有 K 路有序因果归并算法。
- 不读写文件，不持有锁，不访问 Git。

## AXIOM
1. [使用者] 多个 writer 各自追加的事实，合在一起后一条都不能丢，也不能因为谁先到、谁的时钟快而换一种读法。
    - 理由：合法分叉是真实发生的历史；丢一支或单凭时钟挑赢家都会导致状态不一致。

## LEMMA
1. [AXIOM 1] 合并为集合并集：同 id 同字节只留一份；同 id 异字节视为致命身份碰撞，停下报错。
2. [AXIOM 1] 排序结果完全由因果边决定：每个 writer 内顺序不变，父节点先于子节点；并发就绪的节点之间按 EventId 文本序排列，与机器及读取顺序无关。
3. [AXIOM 1] 同一 writerId 只能对应一条完整逻辑流，重复同名流必须拒绝；保留窗口之外的父节点安全放行，窗口内成环报错。

## SPEC（调用方流程）

1. **因果流合并**：
   - 调用方传入一组写入者的事件序列调用 `merge`。算法校验因果依赖与环路，输出确定性的全局线性序列。
2. **冲突与异常检测**：
   - 遇到同 ID 内容不一致抛出 `IdentityCollision`；遇到循环依赖抛出 `NonCanonical`；严格模式下缺失父节点报错拒绝。
