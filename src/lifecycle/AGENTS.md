# lifecycle

层：内核。不得 import 任何宿主 SDK。

# AXIOM

1. [使用者] 一次委托要能连续推进多轮无人值守工作，而每一轮事后都能说清：这一轮为什么发生、什么已经成立、路因此怎么变。
    - 理由：用户买的是省下来的重读。多轮如果说不清，用户就得自己把整条轨迹读一遍，等于买了个更贵的日志。

2. [使用者] 多轮之间，同一时刻只能有一个负责人在动手。
    - 理由：两个负责人同时改同一份工作，会把已完成的成果真的弄坏。这是本包守的唯一不可逆后果。

# LEMMA

1. [本模块 AXIOM 1; 总规则 SPEC 5] 一轮就是一条可复核的记录，由本包在轮末产生，形状不跟宿主走。
    - 推理：AXIOM 1 要求逐轮说清；宿主形状会随宿主变（总规则 AXIOM 2），所以记录的形状必须由本包拥有。

2. [本模块 AXIOM 2] 一条工作同时至多一个活跃任期；每任评审恰好一次，且不得自证；退休不可逆。
    - 推理：任期是"谁现在负责"的载体，评审是"这一任做完了没有"的载体。允许第二任评审、或允许退休者复活，等于把唯一性交还给运气。

3. [本模块 AXIOM 1] 阶段是工作的序列属性，写在开立那一刻；不是全局枚举里的一格，也不是可重放的字段。
    - 推理：AXIOM 1 要的"路因此怎么变"由序列推出。把序列存成"下一步执行什么"，就多出一份能与事实打架的状态。
