# lifecycle — 工作生命周期与澄清询问单飞

层：内核。独立 npm 入口 `wanxiangli/work`。对象 `Work` 是一条任务生命周期流转的唯一领域所有者；`PlanAskGate` 保证同一工作同一时刻至多一条未结清的澄清询问。

## 状态所有权
- **Work** 独占拥有工作的开立、任期推进（Originator → Successor）、里程碑晋级、评审留下的未结清事项记录与交付请求记录。
- **PlanAskGate** 独占持有进程内进行中的澄清询问集合。
- Work 是纯内存自治领域对象，不直接调用底层存储，不直接发起外部进程。持久化合作由外层 `DurableWork` 编排。

## AXIOM
1. [使用者] 开工、评审、接力、交付和恢复必须是一条能持续推进的真实工作，不是散落的工具约定。
2. [使用者] 同一工作至多一任活跃负责人，已退休的一任不能因重放再次动手。
3. [使用者] 持权交付启动执行者是外部效果；不知道启动结果时不能再启动一个。
4. [开发者] Work 是能单独运行的内存对象，不接受存储、宿主或组合者的服务；持有私有状态，以命令和数据记录交流。

## LEMMA
1. [AXIOM 1, 2] 工作开立与首任、接力退休与后任，各是一次原子领域转移；office 开立后不变。
2. [AXIOM 1, 2] 里程碑由 Plan 与 Manager 两阶段推进；发起询问、执行接力与收尾结案都要求未结清事项已清空，结案还须无真实阻塞。
3. [AXIOM 2] 命令绑定任期；重复请求返回既有结果，异载荷拒绝；已退休任期无法继续修改状态。
4. [AXIOM 3, 4] Work 记录稳定的 `DeliveryRequested` 事实；`Applied` 仅表示内存已被应用，不代表已落盘。

## SPEC（操作员与调用方流程）

1. **工作开立与里程碑流转**：
   - 操作员发起新任务，开立 Work 并指定首任负责人。
   - 负责人通过评审推进里程碑（事实取舍 → 理解路径 → 流程伪代码 → 待执行）；未结清事项清空后执行接力。
2. **持权交付与执行认领**：
   - 进入待执行阶段后生成交付请求；外层持久确认后启动执行者；执行者完成并解除阻塞后，进入收尾并最终结案。
3. **澄清询问单飞 (PlanAskGate)**：
   - 交互过程中发起澄清询问时，通过 `PlanAskGate.tryBegin(workId)` 竞争独占权，防止同一工作并发重复发起多个询问弹窗；完成后幂等释放。
