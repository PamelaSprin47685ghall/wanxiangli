# segments — 段文件命名与流解码

层：内核纯计算。独立 npm 入口 `wanxiangli/segments`。在总流程中，本模块负责持久化事件日志段文件的命名规则、序号连续性检查、多段有序拼接，以及旧式单文件与分段并存时以哪一边为数据流。

## 状态所有权
- 独占拥有段文件名（`<writerId>-dddd.ndjson`）的词法规则与序号解析逻辑。
- 纯计算库：不直接读写磁盘，不调用底层存储 API。

## AXIOM
1. [使用者] 一个 writer 写下的全部事实，重新打开后必须作为同一条逻辑流读回；目录里多出一个怪名字不能让整个存储打不开，也不能把一个 writer 的流拆成两个。
    - 理由：段名就是持久格式的一部分；名字读错要么丢流要么串流。

## LEMMA
1. [AXIOM 1] 段名格式必须严格为 `<writerId>-dddd.ndjson`，`dddd` 为 4 位 ASCII 数字（0000..9999），越界报错。
2. [AXIOM 1] 同一前缀的段必须从 0000 起连续递增，否则降级按旧式完整 stem 处理。
3. [AXIOM 1] writer 流是完整规范行序列：以 LF 结尾，行内非空，每行严格按规范解码，遇首处格式破坏即止。
4. [AXIOM 1] 旧式单文件与段系列并存时由 `coexistence` 比对字节：旧式是段系列（按序拼接）的字节前缀（含相等）时以段系列为数据流；段系列是旧式的字节前缀时以旧式为准；两者互不包含、都是完整规范 NDJSON 且事件不相交时按序续接（段系列后接旧式行）；其余为分歧。

## SPEC（调用方流程）

1. **文件名解析与校验**：
   - 传入文件名列表，库将其分类为规范段集合或旧式单文件；非法序号或格式损坏明确报错。
2. **流解码与完整性检查**：
   - 逐行解析文本流。未以换行符结尾判定为中断写入半行；解析出空行或损坏行立即报错中断。
3. **并存时取哪边**：
   - 遇到单文件与分段文件并存时，调用 `coexistence` 比对两边字节，返回 `series`、`legacy`、`continuation` 或 `diverged`；按结果执行物理收敛归调用方。
