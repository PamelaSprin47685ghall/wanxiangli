# admission-queue — 执行准入等待队列

层：内核进程内状态。独立 npm 入口 `wanxiangli/admission-queue`。在总流程中，当并发执行达到系统上限时，本模块提供有界、公平（FIFO）的进程内准入等待队列，确保会话按序获得执行容量，避免插队或饿死。

## 状态所有权
- 独占管理内存中按 FIFO 排队的等待节点（node）列表及会话映射。
- 默认容量上限 32；不直接签发容量许可，不维持后台轮询定时器。

## AXIOM
1. [使用者] 容量不足时等待中的执行按到达先后公平地得到容量；同一次执行不排两次队，被替代或取消的执行不再占位。
    - 理由：防止插队或单个会话垄断并发；残留的废弃等待会阻塞后续任务。

## LEMMA
1. [AXIOM 1] 每个会话至多一个等待项。同物理消息重复入队直接复用原节点；更新物理消息时替换旧节点并排至队尾。
2. [AXIOM 1] 队列容量有界；队列满时新会话拒绝入队，不挤掉已有等待者。
3. [AXIOM 1] 仅当前有效的等待节点可被认领；撤回操作严格针对当前物理消息，陈旧撤回安全忽略。

## SPEC（调用方流程）

1. **请求入队**：
   - 调度器发现并发已满时调用 `enqueue`。若队列未满则加入队尾并返回等待节点；同消息重复入队返回 Reused；队满时明确拒绝。
2. **出队认领**：
   - 容量释放时调用方认领队头节点；认领成功后节点移出活跃队列，执行单元转入执行。
3. **主动撤回与排空**：
   - 会话取消或超时时通过 `withdraw` 移出等待；会话关闭支持 `drain` 批量按序回收全部等待项。
