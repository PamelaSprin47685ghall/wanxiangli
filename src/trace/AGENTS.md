# trace — 确认轨迹与固定取材边界

独立内存库，公开入口 `wanxiangli/trace`。不依赖 Work、Journal、ProcessSession、宿主或压缩器。原草稿的逐字节保留、只追加、独立游标和单一终态继续承接；下面明确本轮选择的协议，不冒称旧宿主已经接入。

## AXIOM
1. [使用者] 已确认的原始材料不能被后来的呈现、压缩或接力改写，用户原文必须逐字节取回。
   - 理由：没有原件，就无法核对系统是否曲解了委托。
2. [使用者] 同一段工作应有固定取材范围；重复观测、晚到回执和宿主重排不能悄悄移动已经给出的边界。
   - 理由：不同读者需要指认同一份材料，而不是各自最近看到的数组。
3. [开发者] 轨迹规则、字节存储和宿主观察分别负责，轨迹对象没有服务依赖。
   - 理由：确认什么、保存什么和如何落盘不是同一职责；普通数据足以完成组合。

## LEMMA
1. [AXIOM 1, 2] 本轮采用单观察者的顺序记录：Opening、RunStarted、MessageObserved、PartConfirmed、MessageFinished、RunFinished。身份重复且内容相同返回原游标，冲突零追加；游标只在首次接受时增加。
   - 推理：稳定身份用于去重，游标用于本轨迹的观察顺序；不把 provider 时间或宿主下标当成本地顺序。
2. [AXIOM 1] 消息来源、角色与运行关联显式给出并冻结；部件是已确认的完整字节块，不是可覆盖的流式候选。部件按消息内 index 连续追加，完成后只接收原事实的重放。
   - 推理：若将临时文本当作原件，下一次更新只能改写历史；单独捕获已确认部件无需复制一份可变草稿。
3. [AXIOM 1, 2] 每个运行只接受一个终态，结束前已观察的消息必须完成；未知不是终态。消息文本不能修改其来源，也不能生成运行结束事实。
   - 推理：终态意味着本次捕获闭合；晚到的缺失材料须由宿主适配先排好次序，不猜测或修补。
4. [AXIOM 2] 边界包含 traceId、游标及该前缀摘要；区间为 (after, through]。原始观察按自身游标取材，消息视图按消息首次观察游标选入，内容只读到 through。窗口另列 through 之前的全部 human 原文，最后一条已完成助手散文只是引用视图。
   - 推理：消息后续部件不能把前任消息搬到后任；固定上界不能偷看后来发生的完成或终态。原文保留与当前任期取材是两个不同视图。
5. [AXIOM 1, 2, 3] 导出是规范 JSON、原始字节的规范 base64 和顺序摘要链；恢复检查整条已提供历史。内存接受不是持久提交；真实组合者先提交，才发布 durable 成功。
   - 推理：格式和哈希能发现记录损坏和断链，但不证明身份真实性；没有另存的可信边界，合法历史前缀的尾部截短不能自行识别。

## SPEC
1. [LEMMA 1] Opening 只能在首条出现且不能改写；同一事实重放返回原记录，字段或内容冲突不改状态。不同消息允许交错，消息内缺 index 则拒绝。
   - 证明：`tests/001.test.mjs` 验证连续游标、原位置重放、开场冲突、消息交错与身份碰撞；全部通过。
2. [LEMMA 2] bytes 接受普通 Uint8Array/Buffer 的副本，包括 BOM、NUL、非 UTF-8；文本视图严格解码，失败返回 null，不替换字节。来源不猜测，元数据不变。
   - 证明：`tests/002.test.mjs` 验证 BOM/NUL/CRLF、组合字符、任意字节、严格文本、显式来源、容量与底层视图覆盖反例；全部通过。
3. [LEMMA 2, 3] 运行先开始，助手/tool 消息才可关联；消息先完成，运行才可结束。新事实不得进入已完成对象，完全一致的旧事实仍可重放。
   - 证明：`tests/003.test.mjs` 验证缺失运行、未完成消息、迟到新事实、终态冲突及旧事实重放；全部通过。
4. [LEMMA 4] 固定窗口在追加后保持相同；外来轨迹、不同分叉、倒序与越界边界拒绝。正文只取已完成助手的 text 部件，不含 tool-call/tool-result；原始观察仍保留全部字节。
   - 证明：`tests/004.test.mjs` 验证追加后固定窗口不变、前任迟到部件、原件保留、最后助手散文和分叉边界拒绝；全部通过。
5. [LEMMA 5] 恢复拒绝不规范编码、未知字段/事件、重复身份、缺口、断链、摘要错误和领域顺序错误；不跳过、不修复。以保留的可信 through 检查尾部是否缺失。
   - 证明：`tests/005.test.mjs` 验证损坏记录、重算哈希后的非法领域状态、截尾边界和确定性重放；安装包的 Node/Bun 真实 SQLite 强杀恢复也通过。不能据此宣称认证来源或断电行为。
6. [AXIOM 3; 根 LEMMA 3, 4, 5] 实例、消息与返回视图无可变别名；拒绝访问器输入和重入。删除前两刀的源码及产物，仍可构建、运行和按原字节恢复。
   - 证明：`tests/006.test.mjs` 检查生成对象、数据别名、实例隔离和重入；隔离构建及安装后删除前两刀产物的 Node/Bun 验收均通过。整个 0.4.0 回归为 204 项通过。

## 边界

- 本轮明确选择单观察者总序，不做多副本归并或并发日志合流。traceId 是一条观察轨迹的范围，不声称是全局时间。
- 普通 append 只表示内存接受；对象不调用磁盘。组合实例应独占自己的 Trace 候选，提交后发布；SQLite 的物理承诺由 Journal 给出。
- 来源与 confirmed/terminal 事实由适配方如实提供，不从正文或未知来源推断；这不是鉴权系统，也不是恶意同进程代码的沙箱。
- 单个 byte 部件上限 512 KiB，记录上限 1 MiB；总历史不静默淘汰，内存随历史增长。大附件可由调用者明确分成独立已确认部件，不假装保存了未提供的原件。
- 固定窗口和最后助手散文不是完整 LWR，也不生成摘要，不计算 token 或改写 provider 请求。压缩、真实宿主接线和旧代码退出仍未实现。
