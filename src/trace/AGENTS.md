# trace — 确认轨迹与固定取材边界

独立内存库，公开入口 `wanxiangli/trace`。在总流程中，本模块为执行会话提供保真、纯追加的事件轨迹记录与固定取材窗口，确保用户指令与模型输出以原始字节形式无损留存，不被后序摘要或压缩篡改。

## 状态所有权
- **Trace** 实例独占拥有单观察者顺序记录与游标，不持有磁盘或数据库连接。
- 组合者（Journal）负责将 Trace 记录持久化至底层介质。

## AXIOM
1. [使用者] 已确认的原始材料不能被后来的呈现、压缩或接力改写，用户原文必须逐字节取回。
2. [使用者] 同一段工作应有固定取材范围；重复观测、晚到回执和宿主重排不能悄悄移动已经给出的边界。
3. [开发者] 轨迹规则、字节存储和宿主观察分别负责，轨迹对象没有服务依赖。

## LEMMA
1. [AXIOM 1, 2] 采用单观察者顺序记录：Opening → RunStarted → MessageObserved → PartConfirmed → MessageFinished → RunFinished；同身份重放幂等返回原游标，冲突零追加。
2. [AXIOM 1] 消息部件为已确认的完整字节块，按消息内 index 连续追加，支持非 UTF-8 原始字节无损存储。
3. [AXIOM 1, 2] 运行与消息具备严格终态；固定取材窗口按游标界定区间，不随后续追加而漂移。

## SPEC（调用方流程）

1. **轨迹事件追加与保真捕获**：
   - 随交互进行依次追加开场、运行启动与消息观测；相同事件重放返回原记录，冲突事件拒绝变更。
2. **消息部件确认**：
   - 收到模型输出流时逐块追加已确认部件，完成后标记消息结束。原始字节完整留存，文本视图严格解码。
3. **固定取材窗口导出**：
   - 调用方通过 `window` 提取指定游标区间的历史事实。区间内的消息视图与用户原文严格冻结，支持前缀复核。
