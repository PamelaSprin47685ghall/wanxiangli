# delivery — 交付视图格与游标管理

层：内核纯数据管理。独立 npm 入口 `wanxiangli/delivery`。在总流程中，本模块负责记录任务执行过程中的最新交付结果、维护交付围栏（providerRun, toolCallId），并追踪已交还接收方的材料游标，防止重复交还或漏交。

## 状态所有权
- **Delivery** 实例独占拥有当前会话的交付格、暂存格以及已交付材料游标字典。
- 纯内存管理：不直接持久化，不决定任务完成条件。

## AXIOM
1. [使用者] 交付必须绑定产生它的那一次调用；呈现一份视图不等于交付。
2. [使用者] 同一份材料只交还一次，变化的材料仍要看见。

## LEMMA
1. [AXIOM 1] 区分带调用围栏的交付格与不带围栏的暂存格；暂存格不能覆盖交付格。
2. [AXIOM 1] 取走交付格时 providerRun 与 toolCallId 必须同时匹配，任一不匹配返回 `fence-mismatch` 且格不改变。
3. [AXIOM 2] 已交还游标仅在兑现（`handOff`）时推进；普通观察不推进游标；选材失败时材料保留在原格。

## SPEC（调用方流程）

1. **交付记录与暂存**：
   - 工具产生输出时调用方记录交付格（附带精确运行围栏）或暂存格。
2. **提取与围栏校验**：
   - 调用方取走交付内容时传入当前调用的 providerRun 与 toolCallId。两者都与交付格里记的围栏对上才交出内容；任一错配返回 `fence-mismatch`，交付格保持原样，不误交他人产物。
3. **材料兑现与游标推进**：
   - 接收方确认消费材料后调用 `handOff`。系统记录已交还游标，后续调用不再重复返回相同材料。
