# delivery — 交付视图格

层：内核。入口 `wanxiangli/delivery`，导出工厂 `Delivery()`。不依赖本仓任何其他模块，不读时间、不做 I/O。

承接主仓 `Repository/Programming/Js/DeliveredValues` 的状态职责（CUT-06）：每个会话最近一次 `deliver(view)` 或暂存视图、产生交付的调用围栏，以及已经交还给接收方的材料游标。三段式 WorkRecord 已由主仓 `6eef89d1e` 退役；本模块替代原 `workrecord` 草稿，不复活三段式记录。

## AXIOM

1. [使用者] 交付必须绑定产生它的那一次调用；呈现一份视图不等于交付。
    - 理由：旧回合、旁路缓存或散文都能伪造"已交付"，任务就会在没有交出东西时被关闭。
2. [使用者] 同一份材料只交还一次，变化的材料仍要看见。
    - 理由：重复交还会让接收方反复读同一段话；吞掉变化又会丢失真实进展。

## LEMMA

1. [本模块 AXIOM 1] 格分两层：带围栏（providerRun, toolCallId）的交付格，和不带围栏的暂存格。只有交付格回答 take / peek / fence；暂存格不能覆盖交付格。
    - 推理：降级会抹掉拥有交付证据的那次调用。
2. [本模块 AXIOM 1] 按 provider run 取走时，只认围栏上的同一 run；旧 run 的终态不能取走新 run 的交付，反之亦然。
3. [本模块 AXIOM 2] 已交还游标只由取走（cache / run）推进；peek 只是呈现，不推进。
4. [本模块 AXIOM 1, 2] 视图不透明：本对象不解析、不渲染、不选材。选材由组合者按 claim 时的视图完成，再以一次性凭据交回；本对象只判断哪些材料尚未交还。
    - 推理：选材依赖锚点账本与请求投影，那是别的 owner；把它们注入这里会扩大依赖。

## SPEC

1. [LEMMA 1] 交付格与暂存格的读写分层；暂存不覆盖交付。
    - 证明：`tests/001.test.mjs`。
2. [LEMMA 2] run 围栏不匹配时 claim 返回 null，格保持原样。
    - 证明：`tests/002.test.mjs`。
3. [LEMMA 3] 游标只在取走时推进；同一材料不再交还，散文以"会话 + 长度 + 前 24 码元"去重且仅在格有视图时附带。
    - 证明：`tests/003.test.mjs`。
4. [LEMMA 4] 凭据只能由签发实例兑现一次；accessor 字段在读取前被拒绝；会话与实例互相隔离。
    - 证明：`tests/004.test.mjs`。

## 不做

- 不持久化：进程重启丢弃全部格与游标；崩溃恢复读宿主的持久交付见证，不读现成字符串。
- 不判断任务是否完成；交付条件、接力与中断由宿主组合者决定。
