# delivery — 交付视图格

层：内核。入口 `wanxiangli/delivery`，导出工厂 `Delivery()`。不依赖本仓任何其他模块，不读时间、不做 I/O。

承接主仓 `Repository/Programming/Js/DeliveredValues` 的状态职责（CUT-06）：每个会话最近一次 `deliver(carry)` 或暂存声明、产生交付的调用围栏，以及已经交还给接收方的材料游标。声明不透明，材料由组合者选择。

## AXIOM

1. [使用者] 交付必须绑定产生它的那一次调用；呈现一份视图不等于交付。
    - 理由：旧回合、旁路缓存或散文都能伪造"已交付"，任务就会在没有交出东西时被关闭。
2. [使用者] 同一份材料只交还一次，变化的材料仍要看见。
    - 理由：重复交还会让接收方反复读同一段话；吞掉变化又会丢失真实进展。

## LEMMA

1. [本模块 AXIOM 1] 格分两层：带围栏（providerRun, toolCallId）的交付格，和不带围栏的暂存格。只有交付格回答 take / peek / fence；暂存格不能覆盖交付格。
    - 推理：降级会抹掉拥有交付证据的那次调用。
2. [本模块 AXIOM 1] 围栏的完整判断由本对象做：取走交付格时 providerRun 与 toolCallId 必须同时相同，只有一个相同即不匹配；不匹配时给出确切原因（`fence-mismatch`），格与游标都不动。
    - 推理：把围栏判断拆到调用方，就等于让每个调用方各记一半调用身份，判断就成了调用方的义务。
3. [本模块 AXIOM 2] 已交还游标只在兑现（handOff）时推进；观察（peek / observe）只是呈现，不推进。
4. [本模块 AXIOM 1, 2] 声明不透明：本对象不解析、不渲染、不选材。组合者按凭据里的声明与调用围栏选择旧材料并附上当前报告，再以一次性凭据交回；本对象只判断材料身份是否已交还，不解释正文。
    - 推理：选材依赖锚点账本与请求投影，那是别的 owner；把它们注入这里会扩大依赖。
5. [本模块 AXIOM 2] claim 不消费：格与游标在 handOff 校验通过之后才动。选材失败时材料留在原格，兑现不成的凭据不推进任何游标。
6. [本模块 AXIOM 2] 凭据由签发实例独占，且只对签发时的那一个格有效：格被取走、被替换，或该会话被 clear / clearAll 之后，旧凭据一律作废，不能再推进游标。

## SPEC

1. [LEMMA 1] 交付格与暂存格的读写分层；暂存不覆盖交付。
    - 证明：`tests/001.test.mjs`。
2. [LEMMA 2] 围栏不匹配时 claim 给出确切原因，格保持原样；run 模式不取暂存格，cache 模式不取交付格。
    - 证明：`tests/002.test.mjs`。
3. [LEMMA 3, 4] 游标只在兑现时推进；同一旧材料不再交还。当前报告的身份由组合者绑定当前调用，不能靠文本长度或前缀猜测两份报告相同。材料顺序与显式重复原样保留。
    - 证明：`tests/003.test.mjs`。
4. [LEMMA 4] 凭据只能由签发实例兑现一次；accessor 字段在读取前被拒绝；会话与实例互相隔离。
    - 证明：`tests/004.test.mjs`。
5. [LEMMA 2, 5, 6] 围栏整体比较；选材失败不丢材料；一次只兑现一次；clear 与 clearAll 之后旧凭据作废。
    - 证明：`tests/005.test.mjs`。

## 不做

- 不持久化：进程重启丢弃全部格与游标；崩溃恢复读宿主的持久交付见证，不读现成字符串。
- 不判断任务是否完成；交付条件、接力与中断由宿主组合者决定。
- 不按 provider run 单独取走交付格：run 身份与调用身份是一体的，比较半个围栏就是允许别人取走自己的交付。
