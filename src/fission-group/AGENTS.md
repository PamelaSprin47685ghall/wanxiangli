# fission-group — 分道裂变分组与收束

层：内核纯计算与进程内状态。独立 npm 入口 `wanxiangli/fission-group`。在总流程中，本模块负责 Engineer 角色的多分道并发执行编排：全组要么整组准入要么整组拒绝、分道拓扑在准入时固定、完成按亲和路由，并在全部分道齐备后由接管分道统一收束；同一 owner 同时只允许一次活跃分组。

## 状态所有权
- 纯计算定律独占拥有分道状态转移、路由与收束的判定规则。
- **FissionLaneRegistry** 独占持有分道执行绑定注册表。
- **FissionRuntime** 独占持有分组资源、交付与接管的单飞认领集合与静默中断标记。
- **FissionAdmissionRegistry** 独占持有活跃 ownerSessionId 准入单飞集合。

## AXIOM
1. [使用者] 一次 Fission 是同一位 participant 的 lane 集合：整组准入或整组拒绝，lane 次序与身份在准入时固定，之后不漂移。
2. [使用者] 每个 lane 的工作、每个外部亲和绑定、接管与组终局各只有一个值：重放同值是幂等，不同值被拒，不覆盖。
3. [使用者] 组只能在每个 lane 都交出工作、每个 Fission 前的完成都送达每个 lane 后才收束；终局只有一个，收束须由接管 lane 宣布。
4. [使用者] lane 请求、完成路由、环次序与终局 lane 是拓扑性质，不由回调到达次序决定。

## LEMMA
1. [AXIOM 1] 整组准入校验：laneCount >= 2 且参数数量严格一致；已有组同值幂等，异值报冲突；同一 owner 已有活跃组时拒绝重复准入。
2. [AXIOM 2] 事件流转严格检查分道索引与身份，异值拒绝覆盖；仅在全部分道均完成工作且完成全量送达后进入 `convergenceReady`。
3. [AXIOM 3, 4] 收束（takeover）由末尾接管分道在就绪后宣告；单道失败或外部中止触发全组失败终局。

## SPEC（调用方流程）

1. **分组准入与分道初始化**：
   - 调用方通过 `FissionAdmissionRegistry` 锁定准入，传入分道提示词列表发起准入。系统初始化固定拓扑的分道结构，并注册分道绑定。
2. **工作交付与路由分发**：
   - 各分道独立执行，产出完成事件时经路由判定进行广播或定向分道投递；通过 `FissionRuntime` 维护交付认领，消除并发重复交付。
3. **全组收束与接管宣告**：
   - 所有分道完成且全部交付送达后，接管分道发起 `takeover`，原子宣告收束并结算全组产物；清理关联资源并释放准入。
