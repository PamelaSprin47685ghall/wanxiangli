# borrowing — 执行容量借用与托管

层：内核进程内状态。独立 npm 入口 `wanxiangli/borrowing`。在总流程中，本模块管理调度器并发容量的分配、借用与 provider-step 临时占位：确保并发执行不超出配置限制，子会话也能复用父会话持有的容量。

## 状态所有权
- 本模块独占管理进程内的容量令牌（token）、借用记录（谁在用谁的 token）及有界等待队列（上限 32）。
- 不直接调用模型服务，不持有全局调度定时器。

## AXIOM
1. [使用者] scheduler 看到的 `running` 必须等于真实在用的容量：一枚 token 是一次真实占位，借用只改变谁可以用它，从不凭空多出或少掉 token。
    - 理由：防止并发超出配置上限或子会话饿死父会话。

## LEMMA
1. [AXIOM 1] 每次物理执行至多持有一枚 token；新执行优先借用出借方空闲 token，或继承旧 token，或申请新 token；退休中的 token 标记 Retiring，执行彻底完成才归还。
2. [AXIOM 1] provider-step 等待者按到达序号排队且有界；释放会话或物理执行时，对应的等待者被移除，其等待以取消失败收尾。
3. [AXIOM 1] 所有者重新进入执行时，从后代借用中收回自己的 token。

## SPEC（调用方流程）

1. **令牌申请与借用**：
   - 执行单元就绪时申请容量。出借方有空闲 token 时借用它并记下这次借用；没有则申请新 token 或进入等待队列。
2. **执行等待与复用**：
   - 同一个请求（requestKey）带着同一组 fence 再次到达时，复用仍在排队或在途的那一轮，不另起一步；等待者队列超限时拒绝新排队，防范内存泄露。
3. **容量归还与收回**：
   - 执行完成时归还借用令牌；父会话需要执行时主动从借用方收回令牌，恢复自身容量。
