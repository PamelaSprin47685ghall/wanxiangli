# 总规则

本文件约束 `src/` 下全部代码。根目录 `AGENTS.md` 是元规则，讲 AXIOM / LEMMA / SPEC 本身怎么写；本文件讲这些代码为什么存在、边界画在哪里、什么该删。GUIDE 只在根目录一份，此处不重复。

引用约定：根目录的条目写作 `根 AXIOM 10`、`根 LEMMA 5`、`根 SPEC 1`；本文件写作 `总规则 LEMMA 4`、`总规则 SPEC 3`；本文件内部直接写序号；子模块引用自己的条目写 `本模块 3`。子模块的 `AGENTS.md` 沿用本文件的结构。

# AXIOM

1. [使用者] 一次用户委托要能驱动多轮无人值守的工程工作，事后能逐轮说清这一轮为什么发生、什么已经成立、路因此怎么变。
    - 理由：用户花钱买的是省下来的重读。说不出理由，用户就得自己把轨迹读一遍，等于没省。

2. [使用者] 宿主（omp、opencode 或别的）的寿命短于本系统。
    - 理由：宿主会换。绑死一个宿主，换一次就重写一次，用户为同一件事付两次钱。

3. [开发者] 代码分三层：内核不认识宿主；GAP 是唯一认识宿主的一层；组装只接线，不做决定。
    - 理由：只有 GAP 会随宿主消亡。宿主替换的成本因此被关在一层里，内核与组装原样留下。

4. [使用者] 逐个从旧系统抽取真实职责，只允许旧系统通过 npm 依赖新系统。
    - 理由：每一刀都必须成为可用资产；不同时维护两份同职责实现。旧仓的修改另行授权。

5. [开发者] F# 用对象封装职责；局部可变状态只要能减少总体复杂度就允许。
    - 理由：为一个对象内部状态额外建立消息层、折叠层与适配层，不会自动带来独立性。

# LEMMA

1. [根 AXIOM 10; 根 AXIOM 7] 按后果判断不可逆性，不按动作名称判断。请求结果未知时不得重发。
    - 推理：重试、派工、接力也可能真的启动第二个执行者；不能因为名字属于内部流程就把它当作可撤销动作。

2. [根 LEMMA 5] 临时例外集中登记一处：兼容层、开关、废弃接口、做不到正交的耦合对。每项写清使用方与解除条件；写不出使用方与解除条件的，不建；已建的现在就删。
    - 推理：根 LEMMA 5 要求例外集中在一处，不许散在注释里。分散的例外盘不过来，也就无人清理。

3. [AXIOM 2; AXIOM 3; AXIOM 5] 内核只接受自身定义的数据与最小结构契约；对象内部状态不泄露，不建立宿主类型或公共大 Context。
    - 推理：宿主可换，契约不随之变；封装后的局部可变状态不要求调用者了解实现。

4. [AXIOM 1; 根 AXIOM 7; LEMMA 1] 用户原文逐字节保留；模型的话可以重述。
    - 推理：用户原文不可逆（LEMMA 1），而且是逐轮理由的最终依据。模型的话丢了，下一轮可以从 durable 事实重新查出来。两者代价不同，不能共用一条压缩规则。

5. [AXIOM 3; AXIOM 1] GAP 只观测宿主，不猜。
    - 推理：GAP 与宿主同寿。它猜错，内核拿到假事实，AXIOM 1 的“说清”就退化成编故事。宿主没给的事实，标成缺失，不补。
