# 回调工作的接纳与排空

本模块让组装方在卸载、关闭或取消入口时收完已接纳的回调，再释放底层资源。它只拥有接纳开关、在途数、等待者和后台错误；宿主订阅、provider、PTY、日志与资源释放次序仍归组装方。

run 与 background 都在返回前同步检查接纳、登记并启动回调。run 将本次同步 throw 或异步 reject 原样交给调用方，finally 放行，不写后台错误。background 观察并保存错误，返回的 Promise 正常完成。错误槽保留最后被观察到的后台错误，包含 null/undefined；不会因读取、成功任务或下一忙期自动清空。

waitIdle 等当前在途数归零，不关闭接纳；当期观察等待者同时释放，下一忙期使用新的等待者。close 在返回前永久关闭接纳，再等待已经接纳的工作；重复调用可等待相同收尾。关闭后 run/background 不执行回调，返回已完成 Promise，不报新的关闭错误，也不取消已接纳工作。

waitIdle/close 结束等待后读取实际错误槽，返回 `{ok:true}` 或 `{ok:false,error}`，不冻结调用时的错误快照。观察等待与关闭等待保留各自释放顺序，不把后一忙期重新挂到已经完成的等待上。

回调内可以再提交：关闭前接纳，关闭后忽略。回调等待自己所在 scope 排空会自等待，保持这个调用限制，不加检测器。排空只表示这些回调已结清，不表示远端程序或 provider 已停止。不引入超时、重试、取消或通用 shutdown 框架。
