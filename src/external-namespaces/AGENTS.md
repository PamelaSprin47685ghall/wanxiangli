# external-namespaces — 外部工具命名空间事实

层：内核进程内状态。独立 npm 入口 `wanxiangli/external-namespaces`。在总流程中，本模块自治持有进程级 MCP 命名空间的已声明集合，接收宿主提供的真实名称，为工具投影和调用边界提供严格前缀判定。

## 状态所有权
- 进程内自治对象独占持有已声明的外部工具命名空间单调并集集合。
- 库不读取具体 SDK、配置文件、角色定义与持久日志；配置解码与授权留在外侧。

## AXIOM
1. [使用者] 历史配置已经向活会话公开的外部工具命名空间，在配置重载或另一个工作区载入后仍必须由运行时识别；不能因丢失旧名称而跳过执行拒绝。
2. [使用者] 本轮配置只向模型公开本轮实际声明的命名空间，不因进程历史并集扩大当前配置的工具投影。
3. [开发者] 外部工具识别不产生领域能力或授权；一个工具能不能用由外层的角色准入决定（宿主 / 万象通），与「它属于哪个命名空间」是两件事。

## LEMMA
1. [AXIOM 1] 每次 declare 只能增加此前未声明的名称，重复及空数组保持状态不变。进程 owner 不提供撤销动作。
2. [AXIOM 2] patterns 只映射调用方本次输入，保留顺序与重复项，不把整个历史集合偷偷拼入输出。
3. [AXIOM 1, 3] matches 使用原始大小写与严格 server + 下划线前缀；不枚举或许可任意具体工具。配置字段 enabled 的物理解码属于宿主，不进入库。

## SPEC（调用方流程）

1. **命名空间声明**：
   - 宿主传入当前配置中声明的命名空间数组调用 `declare`。库将新名称单调追加到进程已知集合中；传入重复名称或空数组时保持集合不变。
2. **当前模式投影**：
   - 宿主传入当前轮次的模式配置调用 `patterns`。输出严格保留传入项的顺序与重复项，不擅自注入历史已知的其他命名空间。
3. **工具名称匹配**：
   - 调用方传入具体工具名进行前缀判定。只有当工具名以已知 server 标识严格后跟下划线（`<server>_*`）且大小写匹配时，判定为匹配；普通工具名或未声明 server 返回 false。
