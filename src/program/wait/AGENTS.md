# wait — 显式时间与因果等待（等待部分）

在总流程中，本模块为执行会话提供因果等待登记、信号与超时竞态结算、等待依赖前沿纯算法分析以及完成邮箱机制。

## 状态所有权
- 本模块独占管理进程内因果等待注册表与等待状态转换。
- 本模块仅提供纯内存算法与邮箱通道，不持久化状态，不反向驱动业务决策。

## AXIOM
1. [使用者] 等待观测只解释当前等待，绝不决定业务分支、铸造许可、参与恢复或影响提示构建。
    - 理由：若程序依据诊断快照作决定，观察的时机和故障便会改变业务；观察者不能成为第二份权威。
2. [使用者] 等待由真实事件唤醒，不以盲目轮询或墙钟判断循环推进。
    - 理由：轮询只能反复猜测，还会制造无关活动；竞争等待对外呈现为一个复合观测。

## LEMMA
1. [AXIOM 1] 业务仅获得登记等待并返回租约的写能力（`IWaitObserver`）；快照读取能力仅供外部诊断。
2. [AXIOM 1] 诊断快照与注册表纯属进程内瞬态对象，不持久化，进程重启自然消失。
3. [AXIOM 2] 等待完成、超时或取消时立即移出活跃集合；租约释放操作幂等。
4. [AXIOM 2] `untilSignalOrDeadline` 在真实信号与截止时间之间竞态；信号胜出取消截止句柄，超时到达返回 `WaitTimedOut`，不捏造业务事实。
5. [AXIOM 2] 因果前沿分析为纯算法：沿依赖链推导最小未满足前沿（外部生产者、断裂边、循环、空），仅供观测。
6. [AXIOM 2] 完成邮箱独立拥有物理唤醒通道，支持带超时的等待与批量排空。

## SPEC（调用方流程）

1. **因果等待与超时竞态**：
   - 调用方调用 `untilSignalOrDeadline` 传入信号源与 Deadline 句柄进行等待。
   - 若信号先行触发，立即注销定时句柄并返回信号数据；若定时器先行到期，返回 `WaitTimedOut` 且清理等待状态。
2. **因果链排障诊断**：
   - 外部诊断组件调用前沿分析算法扫描当前活跃等待图，如实返回是否存在依赖环路、断边或外部未满足前沿，供排障呈现。
3. **完成邮箱排空**：
   - 等待者挂起在邮箱通道上；事件到达时唤醒等待者并递交载荷；取消操作幂等唤醒所有等待者并排空邮箱。
