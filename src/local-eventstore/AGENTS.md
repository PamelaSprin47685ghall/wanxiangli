# 本机事件存储

本入口服务根规则的总流程：同一目录里几个写入者留下的事实，后续工作能读回；保存结果尚未确认时，不把它说成没有写入。

## 使用

调用者提供事件目录、共享锁位置、writer 名和领域规则。`LocalIntegrator` 持有各规则的 Current、事件与原文索引；`LocalEventStore` 组织锁、刷新、准备、追加、落盘与提交。两者属于同一完整能力；规则只解释自己的槽位，目录的产品含义由调用者决定。

构造存储时同步读取已有内容。需要延迟打开的应用延迟构造对象。写入原文先取得内容地址，再由追加事件引用；每行仍携带它引用的原文。刷新会更新 Current，不替 Journal 发布本地修订。

`append` 的成功包含锁释放。写入前拒绝、未尝试、结果未知和没有新写入但释放失败分别返回；原因对象原样携带。结果未知后先恢复或查询，不把它当成可直接重发的授权。一次候选只可提交到它读取的 Current；已经写下字节后提交失败，仍是未知。

这里使用现有 NDJSON 格式与公开的 events、segments、convergence、quarantine、file-lock。`wanxiangli/eventstore` 仍是 SQLite Journal；本入口不替换其协议，也不解释任何宿主消息。旧式文件整理沿原协议保留，不增加产品入口或审计策略。

类型和调用边界见 [index.d.ts](index.d.ts)。开发检查就近放在 tests；实际运行结果由主体工作包记录，不在此维护版本完成表。
