# AXIOM

1. [使用者] 谁是子会话、它属于谁、谁负责它的生死，事后要能查清。
    - 理由：查不清就会有会话没人收，进程一直留着。

# LEMMA

1. [本模块 AXIOM 1] 容器分类只看两件事：它是长期工作还是内部叶子；它有主还是挂在别人身上。两者正交。
    - 推理：分类一旦混入角色或用途，同一个容器就会在不同判据下归入不同类，收尾时谁负责就说不清。

2. [本模块 AXIOM 1] 挂载只有一个 owner，且不得以自己为 owner。
    - 推理：两个 owner 会各自认为对方负责收尾；自链会让收尾递归不停。

3. [本模块 AXIOM 1] 挂载关联先落盘，才发第一条提示。
    - 推理：先发提示再落盘，崩在中间就会留下一个不知属于谁的活会话。

4. [本模块 AXIOM 1] 会话标识只是可复用的物理容器，不是身份作用域。
    - 推理：把身份绑在容器上，容器一复用就继承前一个身份。
