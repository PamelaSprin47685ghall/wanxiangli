# assembly — 持久工作组合 (DurableWork)

独立 npm 入口 `wanxiangli/durable-work`。对象 `DurableWork` 是连接内存领域对象 `Work` 与持久化存储 `Journal` 的中介组合者（C）。在总流程中，它保障只有持久落盘提交成功的决策才能触发外部物理动作，杜绝宕机重启后重复执行。

## 状态所有权
- **DurableWork** 独占拥有在途活动调用标记、提交竞争处理以及未知提交状态封存逻辑。
- 组合者不复制 Work 的内部状态，不直接启动子进程或网络调用；工作规则归 Work，存储规则归 Journal。

## AXIOM
1. [使用者] 只有确认持久提交的决定可以触发真实效果；丢回执不能导致再次执行。
   - 理由：决定恢复时是否会重复修改用户成果。
2. [开发者] 工作规则与存储可以分别改变，合作流程只有一个负责人。

## LEMMA
1. [AXIOM 1, 2; 根 LEMMA 4] C 读取 Journal 的记录，向 Work 提供数据并请求应用命令，再把 Work 产生的事件追加到 Journal。
2. [AXIOM 1] 候选 Work 在内存事务中应用变更，但未提交的 `Applied` 绝不对外冒充 `Committed`；提交失败立即丢弃候选状态；提交结果未知时封锁实例等待观察。
3. [AXIOM 1, 2] 同一 DurableWork 实例的并发在途调用互斥，重入调用直接拒绝。

## SPEC（调用方流程）

1. **组合执行与原子提交**：
   - 外层向 DurableWork 提交命令。系统在内存候选上执行业务转移；随后将新产生的事件追加至 Journal。追加成功后返回 `Committed` 及新决策。
2. **幂等重放与冲突防护**：
   - 重复请求返回已提交的既有结果，不重复触发外部副作用；遇到修订号冲突时显式报错拒绝，由外层重新读取最新事实。
3. **未知状态安全封锁**：
   - 若提交过程遭遇未知网络中断或异常，实例进入封锁状态，禁止盲目重试，确保外部效果不会被重复执行。
