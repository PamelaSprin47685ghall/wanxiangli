# time — 显式时间与因果等待（时基部分）

在总流程中，本模块负责提供强类型截止时间计算、确定性虚拟时钟以及统一的物理时序适配器，避免业务逻辑直接依赖不可控的系统墙钟。

## 状态所有权
- 本模块独占拥有强类型 `Deadline` 的算术规则与边界钳制算法。
- 物理时间适配器独占封装系统级 `setTimeout` / `clearTimeout` / `UtcNow`（`nodeTimerPort` / `nodeClockPort`）。
- 模块不持久化时间，不持有会话生命周期，不直接决定业务超时策略。

## AXIOM
1. [使用者] 业务只在显式拿到时钟时才读时间；到期只结束等待，不制造业务事实。
    - 理由：随时读全局时间会让时间变成隐式输入，事后无法复述决策。
2. [使用者] 时序行为可以在虚拟时钟上完全可重复地推演与测试，不依赖物理墙钟等待。
    - 理由：靠真实等待的测试结果不稳定；边界时刻与取消顺序必须完全可重复。

## LEMMA
1. [AXIOM 1] 时钟与定时器都靠显式传入；除 `nodeClockPort` / `nodeTimerPort` 两个物理适配例外，库内不读全局时间、不排全局定时器。
2. [AXIOM 1] 截止时间是“当前时刻 + 预算”算出的强类型值；剩余量、到期判定与下一段等待时长由纯计算得出，并对数值上下界进行安全钳制。
3. [AXIOM 2] 在测试与推演环境中，时钟可替换为确定性虚拟时基，按步进推进事件，取消后推进不再触发。
4. [AXIOM 1] `IDeadlineHandle` 结构契约用于跨模块解耦，消费方通过组合者注入实例。

## SPEC（调用方流程）

1. **截止时间计算**：
   - 调用方传入当前时间与有效预算创建 Deadline。若预算为负数，直接视为已到期；计算剩余时间与下段等待时间时，对极大预算安全封顶至 `MaxTimerWaitMs`，防止数值溢出。
2. **定时器等待与取消**：
   - 调用方通过 `Delay(ms)` 创建等待句柄。到期触发回调通知；在到期前调用取消操作，立即注销定时器并不再产生回调。
   - 虚拟时钟仅在显式调用推进时触发对应区间的定时器，步进精确到毫秒。
3. **退出与延迟的竞争**：
   - 调用 `raceExit` 让一个已有退出任务与一段延迟竞争：退出先到返回 true，延迟先到返回 false。延迟到点只说明等待截止，不代表被等待方已经退出。
