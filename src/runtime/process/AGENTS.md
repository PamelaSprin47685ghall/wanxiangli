# process — 独立的真实进程会话

在总流程中，本模块为外部命令（如 git、构建、分析工具）提供真实的操作系统进程启动、有界管道通信、缓冲区排空与进程组生命周期管理。

## 状态所有权
- `ProcessSession` 独占拥有子进程句柄、输入输出环形缓冲区、活动写入状态及等待注销逻辑。
- 本模块不负责任务阶段划分、持久化日志记录或上层业务重试。

## AXIOM
1. [使用者] 命令和输入会真的改变世界；启动、写入管道、退出是不同事实，不能重复执行或混称成功。
   - 理由：错把超时当未执行会引发重复启动；错把输出当退出会过早进入下阶段。
2. [使用者、开发者] 长命令和大输出不能无限占用本进程内存；仍能交互、查看最近原始输出并明确知道哪些字节已丢弃。
   - 理由：不受控的输出和未排空管道会导致进程死锁或 OOM。
3. [开发者] 这项能力能脱离任务生命周期和宿主单独使用。
   - 理由：物理执行不需要绑定特定业务上下文，合作由外层组合。

## LEMMA
1. [AXIOM 1, 3] 构造时显式传入可执行程序、argv、工作目录、环境变量及输出容量，先验证全部输入再启动。不隐式开 shell，不默认重试。
2. [AXIOM 1] `wait` 等待子进程退出且管道完全排空关闭；到期返回 `TimedOut`，不发送信号、不修改退出状态。`signal` 向子进程所属进程组发送信号。
3. [AXIOM 1, 2] stdin 一次最多一个有界写入；部分写入后若管道断开保持 Unknown，不自动盲目补写。
4. [AXIOM 2] stdout 与 stderr 分别配置固定容量环形缓冲区并持续排空；溢出时丢弃最早字节并精准报告丢弃量，文本视图保留末尾字符边界。

## SPEC（调用方流程）

1. **进程启动**：
   - 调用方传入绝对程序路径、参数列表与配置构造 `ProcessSession`。参数非法或路径缺失直接拒绝；成功启动后返回独立会话对象。
2. **输入与输出排空**：
   - 调用方通过 `write` 发送输入，通过 `endInput` 关闭输入通道。
   - 子进程产生大输出时，环形缓冲区自动丢弃最早超出部分，保持常驻内存在预算以内；读取时返回副本及精确丢弃字节数。
3. **等待与信号干预**：
   - 调用方通过 `wait(timeoutMs)` 阻塞等待进程完成。若超时到达，返回 `TimedOut` 且进程继续运行；调用方可依策略通过 `signal` 升级发送 SIGTERM 或 SIGKILL 信号终止进程。
