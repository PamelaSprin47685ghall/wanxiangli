# pty — 真实伪终端会话

在总流程中，本模块为需要真实交互式终端环境（TTY、ANSI 控制序列、尺寸感知）的命令行任务提供底层伪终端会话封装与生命周期回收。

## 状态所有权
- `Terminal` 对象独占拥有底层终端驱动子进程连接、输入输出管道及进程组回收逻辑。
- 伪终端驱动（如 bun-pty）由组合者显式注入，本模块不强绑定特定宿主运行时。

## AXIOM
1. [使用者] 终端就是终端：程序看到的是 tty，不能用管道冒充；写入、读取、信号、尺寸都作用在同一个真实会话上。
   - 理由：交互程序在管道下行为不同，冒充会让调用方基于假行为工作。
2. [使用者、开发者] 关闭一次会话后不留后代：整个进程组被回收，忽略 TERM 的程序会被升级到 KILL。
   - 理由：孤儿进程会持续占用系统资源，并在下一次运行中制造幽灵副作用。
3. [使用者] 每个动作如实报告结果：失败的动作、真实错误码；会话已退出时明确说 `Closed`，不假装写入成功。
   - 理由：退出后静默成功会让调用方以为输入已送达。

## LEMMA
1. [AXIOM 1, 3] `Terminal.open` 先校验所有参数与工作目录存在性，再调用驱动启动命令。驱动失败返回 `Failed{operation: 'spawn'}`。
2. [AXIOM 1] `read(waitMs)` 读取已缓冲输出；缓冲为空且会话活跃时挂起，首个字节到达立即返回，超时未收到输出返回空串。同一时刻只允许一个挂起读，并发读返回 `Busy`。
3. [AXIOM 3] 退出后执行 write、signal、resize 操作一律返回 `Closed`。
4. [AXIOM 2] `close(graceMs)` 向所属进程组发送 TERM 信号并等待宽限期；超时未退出升级为 KILL 信号，确保无残留孤儿进程。

## SPEC（调用方流程）

1. **终端创建与参数核对**：
   - 调用方通过 `Terminal.open` 传入目标命令、工作目录及行列尺寸。若工作目录不存在，立即返回 ENOENT 错误；驱动启动成功后返回会话实例。
2. **终端交互**：
   - 调用方通过 `write` 发送终端输入；通过 `read` 提取终端回显与程序输出；通过 `resize` 动态调整终端长宽尺寸。
   - 若进程已退出，任何后续操作返回 `Closed`，不产生错误副作用。
3. **会话关闭与清理**：
   - 任务完成或取消时调用 `close`。系统向进程组发信号退出并回收资源；已退出的会话重复调用 `close` 幂等返回 `AlreadyExited`。
