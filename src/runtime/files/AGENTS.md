# fs — 文件读取、锚点与原子编辑

在总流程中，本模块为工具调用与代码操作提供严格编码的文件读取、基于字面量的精准锚点匹配、gitignore 感知的文件枚举与多文件单意图原子编辑回滚机制。

## 状态所有权
- 本模块独占拥有文件读快照比对、纯编辑事务决策、锚点区间计算与多文件原子写盘/回滚逻辑。
- 库不持有会话角色、LLM 权限或持久事务日志。

## AXIOM
1. [使用者] 文件字节是事实：读取返回原始 UTF-8 文本，坏编码与 NUL 字节拒绝为 `INVALID_UTF8`，绝不静默替换。
    - 理由：把二进制当文本改写会无声破坏用户文件；明确拒绝优于破坏。
2. [使用者、开发者] 多文件修改要么全部落盘，要么全部不发生；失败回滚只还原自己写下的内容，第三方修改被保留。
    - 理由：半提交状态会导致工程破损；覆盖他人写入等于破坏并发工作。
3. [开发者] 本能力脱离角色权限、JS 沙箱与宿主单独成立。
    - 理由：文件操作逻辑独立于上层权限；权限组合由外层编排。

## LEMMA
1. [AXIOM 1] 读取采用严格解码；文件不存在归类为 `FILE_NOT_FOUND`，坏编码或含 NUL 归类为 `INVALID_UTF8`。
2. [AXIOM 1; 根 LEMMA 3] 锚点按声明顺序在不可变文本上严格匹配；未声明 occurrence 时必须满足唯一匹配（非唯一报 `ANCHOR_NOT_UNIQUE`）。
3. [AXIOM 3] 目录枚举遵守各级 `.gitignore` 与 `.git/info/exclude`，不递归进入 `.git` 目录，不跟随符号链接。
4. [AXIOM 2] 纯事务决策仅依据当前磁盘快照与预检规则生成执行/回滚计划。
5. [AXIOM 2] 写盘前逐条校验当前内容等于预期快照，任一文件校验失败即终止并按回滚计划安全还原已写文件。
6. [AXIOM 3] 路径解析严格校验目标在工作区根目录以内，拦截路径遍历逃逸与指向根外的符号链接（`PATH_DENIED`）。

## SPEC（调用方流程）

1. **安全读取**：
   - 传入相对路径读取文本。文件不存在返回 `FILE_NOT_FOUND`；遇到非法 UTF-8 字节返回 `INVALID_UTF8`；成功返回原始文件内容与版本快照。
2. **锚点检索与替换**：
   - 传入原始文本与锚点定义。未指定序数时若匹配到 0 个或多个位置，返回歧义错误；若唯一定位则返回精确的 UTF-16 起止区间。
3. **多文件原子编辑**：
   - 提交一组文件写入/重写意图。系统首先执行 preflight 预检，核对快照一致性与路径合法性；预检通过后按序落盘。
   - 若某文件落盘失败，立即启动回滚计划，仅将本批次已修改的文件恢复至原始快照内容，第三方并发修改不予触碰。
