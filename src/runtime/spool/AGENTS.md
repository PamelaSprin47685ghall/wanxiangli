# spool — 有界内存与完整输出外存

在总流程中，本模块为外部命令执行和进程输出提供有界内存缓冲与外存转储能力，防止长命令的大量输出耗尽宿主内存，同时保障最终交付能完整取回原始输出字节。

## 状态所有权
- `OutputSpool` 独占管理当前输出字节缓冲、溢流外存文件句柄及写入字节计数。
- 本模块不负责启动进程，不判断输出内容，不决定业务截断策略。

## AXIOM
1. [使用者] 需要完整输出时，本对象交出的每一个字节都与观察到的原始字节相同，顺序与到达顺序相同；不能把留尾说成完整。
   - 理由：外存只有在可以完整重读时才有意义；丢字节而报完整会让调用方基于错误材料继续工作。
2. [使用者、开发者] 内存只持有显式上限内的字节；超过上限后全部字节转入一个文件，内存不再积压。
   - 理由：长命令可能产生任意多输出，常驻内存会拖垮整个宿主。
3. [使用者] 外存失败必须如实说出：失败的动作、真实错误码、已写入多少字节。
   - 理由：磁盘满、目录权限等属于真实环境故障；吞掉错误会导致无法诊断。

## LEMMA
1. [AXIOM 1, 2] `append(channel, bytes)` 复制输入。累计未超过 `memoryBytes` 时保留在内存；首次超过上限时，按到达顺序将全部字节写入独占临时文件，此后直接追加落盘。
2. [AXIOM 3] 打开或写入文件失败后进入 `Failed` 状态：释放内存缓冲，关闭文件，此后仅计数丢弃字节，不再写入，不盲目重试。
3. [AXIOM 1] `finish()` 一次性封口，重复调用返回副本；封口后迟到的输出被拒绝并不再计入。`discard()` 物理删除自身创建的临时文件。
4. [AXIOM 1] 支持分块完整重读（`readChunks`）与末尾安全读取（`readTail`），尾部读取自动对齐 UTF-8 字符边界并报告跳过字节。

## SPEC（调用方流程）

1. **追加输出流**：
   - 调用方通过 `append` 传入 stdout 或 stderr 字节块。未超限前两路数据在内存中保真暂存；超限后自动创建独占文件并合并追加。
   - 若写入过程中遭遇磁盘写满或权限不足，状态转为 `Failed`，如实返回错误码及已落盘字节数。
2. **输出读取与分块**：
   - 命令执行结束后调用 `finish` 封存输出。
   - 调用方可通过 `readChunks` 逐块提取全部原始输出，或通过 `readTail` 提取末尾指定预算的字节，切口处自动跳过半个 UTF-8 续字节。
3. **资源清理**：
   - 调用方消费完毕后调用 `discard`，安全删除对应的临时磁盘文件并释放资源。
