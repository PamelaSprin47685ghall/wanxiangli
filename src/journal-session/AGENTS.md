# Journal 会话

本入口服务根规则的总流程：已经保存的事实能唤醒后续工作，关闭时排空已经接受的追加；没有提交的请求不冒充新的可见修订。

`JournalWriter` 持有懒初始化、追加序号、串行队列、第一次物理失败和关闭过程。`JournalSession` 组织它与 Current 的读取，持有本地修订、等待者和恢复代次。Current 仍属于存储；会话不保存第二份领域投影。共享实例继续交给既有共享池。

打开对象不写入。第一条业务追加前先提交初始化；业务的 ID 在调用时分配，时间和内容在真正轮到执行时生成。成功或已提交的语义拒绝消耗序号，只有成功才推进本地修订并唤醒等待者。刷新 Current 不制造本地提交。

关闭立即停止接收新追加，随后等已接受的前缀结束；重复关闭共享同一个任务。意外 Promise 拒绝照常传播，不吞错续跑。一个等待者取消不消费下一次提交。恢复按代次共享执行，新一代等待前一代；前代拒绝继续向调用者传播。

事实解释、原文编码、父依赖、产品处置与宿主取消令牌由调用者适配。失败类别与原原因分别传递，不根据文案猜测是否已写入；本入口不增加重试、去重或审计策略。具体类型见 [index.d.ts](index.d.ts)，开发差分放 tests，实际运行结果归主体工作包。
