# prefix — 前缀世代与缓存稳定性

层：内核。独立 npm 入口 `wanxiangli/prefix`。对象 `Prefix` 在总流程中负责监控向模型发送的请求前缀，确保上下文具有精确的字节前缀追加性，从而最大化命中 LLM 供应商的前缀缓存（Prefix Caching），降低交互延迟与花费。

## 状态所有权
- 纯计算对象，独占拥有前缀世代（epoch）判定、候选提议与检查点去重规则。
- 不直接读写存储，不发起网络请求。

## AXIOM
1. [使用者] 同样的前缀再发一次，模型那边应当能命中缓存，不要重算一遍。
    - 理由：前缀缓存直接降低延迟与费用。
2. [使用者] 宿主压缩或任期交接真实发生后，旧前缀不再成立；同一次事件不能被当成两次。

## LEMMA
1. [AXIOM 1] 同一世代内，前一次发给模型的请求必须是后一次的精确字节前缀；发生任意字符漂移均不属于追加。
2. [AXIOM 1, 2] 世代只在真实压缩或任期交接确认后推进一次（+1），不按字符计数盲目主动切代。
3. [AXIOM 2] 重放的推进行与同一事件的重复提交视为预期稳态予以吸收，不重复推进；非后继世代判定为损坏并报错。

## SPEC（调用方流程）

1. **前缀继承分类**：
   - 每次生成新请求前调用 `classify`。比对模型、工具集、系统提示与消息历史；若严格保持前缀一致则放行，否则明确报告是哪些字段破坏了前缀。
2. **世代提议与提交**：
   - 发生压缩或接力时调用 `proposeCompaction` 生成候选；确认落盘后调用 `commit` 推进世代编号。
3. **重放与重复事件吸收**：
   - 恢复重放遇到同一事件已推进过时吸收通过、不重复推进；遇到跳号异常时报错拒绝。
