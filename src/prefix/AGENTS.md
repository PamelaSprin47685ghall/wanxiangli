# prefix

层：内核。npm 入口 `wanxiangli/prefix`。对象 `Prefix` 是前缀世代、候选/提交、检查点窗口与同代追加律的无状态 owner。不得 import 任何宿主 SDK、Trace 或存储；持久化与写入由组合者（宿主 C）负责。

来源：宿主仓 `proposals/extraction-kanban/cards/CUT-15.md`；现行需求 `requirements/prefix-stability/WHAT.md` [001][002][004][006][012][013]。

# AXIOM

1. [使用者] 同样的前缀再发一次，模型那边应当能命中缓存，不要重算一遍。
    - 理由：这是省钱，不是安全。本包守的是钱，不是不可逆事实。

2. [使用者] 宿主压缩或 Plan 任期交接真实发生后，旧前缀不再成立；同一次事件不能被当成两次。
    - 理由：每推进一次世代，宿主就清空检查点、退休旧的辅助呈现。重复推进会把会话已重建的覆盖白白清零。

# LEMMA

1. [AXIOM 1] 同一世代内，前一次发给模型的请求必须是后一次的精确字节前缀；否则不是追加。
    - 推理：缓存认的是字节。中间改一个字节，后面全部失配；工具集追加也让缓存整体失效。

2. [AXIOM 1, 2] 世代只由已提交证据推进，且每次恰好加一。证据只有两类：宿主压缩伪 run、Plan 任期 incumbencyId。不按容量或 token 数主动切。
    - 推理：主动切会掩盖实现造成的字节漂移。旧草稿列出的"探针成功、压缩窗口"已被现行需求废除（prefix-stability-003），不传承。

3. [AXIOM 2] 候选只是对下一行的提议，不改变状态；提交才推进。已推进过的证据没有候选，提交时也被拒绝。
    - 推理：压缩消息永远留在宿主记录里，每次核对都会再次观察到它；世代因别的证据前进后，旧证据的新行会带着"正确"的 previousEpoch 到来。世代检查拦重放的行，证据集合拦重复的决定，二者不能互相替代。

4. [AXIOM 2] 重放的行（世代过期）与重复的证据是预期稳态，吸收；非后继世代是损坏，报告。
    - 推理：崩溃恢复会故意重试推进行，吸收使恢复幂等，不需要第二套去重。

5. [AXIOM 1] 已提交的 view 检查点按工具调用身份去重；世代推进时由组合者清空窗口。
    - 推理：同一调用身份重入是同一事实的重放。

# SPEC

1. [LEMMA 1] `classify` 比较 provider、model、variant、完整工具集、system 与逐条消息规范字节；任一项变了都不是追加，并给出全部违例项。
    - 证明：`tests/004.test.mjs` 的方向性、五类身份变化、单字节修改、重排与 200 轮伪随机扩展/修改。语言切换例外（prefix-stability-013 末段）不由本对象判定，由调用方决定是否比较。

2. [LEMMA 2, 4] `commit` 只接受恰好加一的推进；两类证据之外的 kind 抛 TypeError；非后继报 `NonSequentialEpoch` 且不吸收；过期行报 `StaleEpoch` 并吸收。
    - 证明：`tests/001.test.mjs`。

3. [LEMMA 3] `propose`/`proposeCompaction` 不改变输入状态、返回冻结数据；已推进证据无候选；旧压缩在无关推进之后仍被 `AlreadyReanchored` 拒绝；畸形状态被拒而不是补默认值。
    - 证明：`tests/002.test.mjs`。

5. [总规则 SPEC 1] 产物不导入兄弟库或宿主 SDK。
    - 证明：`tests/005.test.mjs` 扫描 `dist/prefix/Prefix.js` 的 import。

# 边界

- 本对象不读宿主请求、不调用 Trace，也不判定缓存是否真的命中；不得用前缀判定反推 authority。
- 消息规范字节由调用方渲染；本对象只逐条比较，不解析消息结构。
