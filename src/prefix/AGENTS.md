# Prefix

`wanxiangli/prefix` 管前缀世代和追加关系，帮助长对话沿用已有缓存，并在实际重锚后重新开始积累。它不读取宿主 SDK、Trace 或存储。组合者负责持久化与其他模块的可见性。

`Prefix` 提供无状态的候选、提交、检查点窗口和同代追加运算。`classify` 比较 provider、model、variant、工具集、system 与消息规范字节；调用方提供这些字节，库不解释宿主消息，也不据此决定权限或声称缓存真的命中。

`PrefixHistory` 拥有当前世代、已处理的 compaction/tenure/scope 身份、上一 Scope 的归档地址与提问回执。推进返回新历史；候选只读。重放、旧世代与非后继仍按既有顺序拒绝，不重复退休其他模块的内容。普通 compaction/tenure 推进保留归档与回执；Scope 归档推进清空提问回执，只有地址与摘要同时存在才保存归档，缺少任一项仍按既有协议推进世代。

提问只能登记在匹配当前世代的上一 Scope 归档上。同一调用与摘要重放返回原历史，不同摘要拒绝。Blob、归档字节和真实提问由调用方处理；回执表示登记，不表示回答已送达。

`state()` 返回冻结的世代视图；归档与身份查询也不交出可改集合。库不执行持久提交，不拥有第二份 Journal。组合者只能以实际提交的事实更新历史。压缩候选从已观测 run 中选择最新未处理的一项；每次提交只推进一代。

就近用例位于 `tests/`；安装消费者在 `scripts/tests/prefix-history-consumer.mjs` 和 `.ts`。它们检查公开入口与本次变化，不能替代宿主真实调用。
